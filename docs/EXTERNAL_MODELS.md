# 외부 모델 사용 설명서

모델의 계산 능력과 조작법을 정리한다. 실험 설계와 모델 연결은 Codex가
질문에 맞춰 판단하며, 입력 파일과 코드는 필요할 때 만든다.
활용 예시는 출력값에서 다음 질문과 계산을 떠올리기 위한 참고다.
Codex는 질문에 따라 예시를 바꾸거나 다른 연결을 만들 수 있다.

## 공통 실행 환경

저장소 루트에서 실행한다. Python 연구 환경은
`.venv-research/Scripts/python.exe`다. 다른 엔진의 실행 파일은
[런타임 경로 목록](../.external-engine-runtimes.json)에서 찾는다.
아래 파일 이름은 실행할 때 준비할 입력을 나타낸다.

```powershell
& .venv-research/Scripts/python.exe -X utf8 experiment.py
```

설명은 로컬 코드·도우미 기준이다. [설치 안내](EXTERNAL_MODEL_INSTALLATION.md)는
과거 설치 이력이며, 이번 문서 수정에서 엔진 전체를 다시 실행한 것은 아니다.
`smoke` 파일은 API·명령을 참고하는 예제이고 필수 실험 절차가 아니다.

## OpenSim — 근골격 역학

- **계산 능력:** 신체 모델의 상태에 따른 역학 계산. 현재 반력 도우미는 지정한 관절의 힘·모멘트를 계산한다.
- **입력 → 출력:** `.osim`, 관절, 상태·제어값 → 반력 N, 모멘트 N·m. 회전 상태값은 rad, 시간은 s.
- **실행법:** 연구 Python에서 `import opensim`. 반력 도우미의 사용법은 아래와 같다.
- **고유 조건:** 모델에 정의된 관절·상태 이름을 사용한다. 도우미는 Windows 한글 경로 문제를 피하기 위해 ASCII 임시 경로에 모델을 복사한다. 상태별 반력 계산과 운동 궤적 적분은 다르다.

```powershell
& .venv-research/Scripts/python.exe scripts/external_engines/opensim_joint_reaction.py --model model.osim --joint knee_r --side child --state-snapshot state.json
```

여러 상태를 계산하는 [도우미의 입력 형식](../scripts/external_engines/opensim_reaction_series.py).

### 활용 예시 — 운동 부하에서 근성장까지 추정해 보기

예를 들어 “같은 운동에서 자세와 중량을 바꾸면 근성장에 어떤 차이가 날까?”라는
질문을 다음처럼 탐구할 수 있다. 아래는 실행된 결과나 고정된 실험 순서가 아닌
연쇄 추정의 예시다.

**운동 조건 → 근육별 부하 → 자극 추정 → 성장 반응 추정 → 갱신된 상태로 재계산**

| 생각을 이어가는 예 | 계산·추정하는 내용 |
| --- | --- |
| 중량·자세·속도·가동범위를 바꿔 본다 | 해당 동작을 표현하는 신체 모델과 운동 입력을 준비한다. |
| 어느 근육에 얼마나 부하가 걸릴까? | 적합한 OpenSim 분석으로 관절 모멘트와 근육별 힘·길이 등을 계산하거나 추정한다. 현재 관절 반력 도우미만으로 이 값이 모두 나오는 것은 아니다. |
| 그 부하는 어떤 자극에 해당할까? | 근육별 힘·길이·부하 지속시간·반복 횟수를 기존 지식과 함께 해석하고, 질문에 맞는 자극 지표나 범위를 계산한다. |
| 그 자극이 성장에 얼마나 기여할까? | 관련 연구나 반응 모델을 현재 근육 상태·훈련 이력·회복 조건과 함께 사용해 성장 반응의 조건부 범위를 추정한다. 이는 OpenSim의 내장 출력이 아니라 추가 추론·계산이다. |
| 몸이 달라진 뒤에도 같은 반응일까? | 추정된 근육 상태와 누적 이력을 다음 계산에 반영해 부하와 반응을 다시 살펴본다. 변화가 지지되는 입력만 갱신하고, 불명확한 값은 범위나 대안 조건으로 다룬다. |

관절 반력만으로 개별 근육의 힘이 정해지는 것은 아니므로 필요한 근육 힘 분석을
선택한다. 힘이나 지속시간을 곧바로 성장량으로 바꾸는 공통 계수는 두지 않는다.
Codex가 기존 지식·모델을 이용해 연결을 구성하며, 필요한 계산 코드는 그때 작성한다.

## Moco — 동작 최적 제어

- **계산 능력:** 설정한 목적함수와 운동 조건에 따른 상태·제어 궤적 최적화.
- **입력 → 출력:** OpenSim 모델, 시간·상태·제어 범위, 목적함수 → 최적화된 시간·상태·제어 궤적.
- **실행법:** `opensim.MocoStudy()`로 문제를 구성하고 `study.solve()`를 호출한다. [로컬 사용 예제](../scripts/external_engines/moco_smoke.py).
- **고유 조건:** 변수 단위는 OpenSim 모델 기준이다. 이 환경의 CasADi 플러그인 경로 설정은 예제의 `CASADIPATH` 부분을 참고한다.

## FEBio — 조직·재료 유한요소 해석

- **계산 능력:** 선택한 재료 모델과 경계조건에서 변형·응력 등의 해석값 계산.
- **입력 → 출력:** `.feb`의 메시·재료·하중·경계조건 → 지정한 해석 출력과 로그.
- **실행법:** 런타임 목록의 `febio` 실행 파일에 `-i model.feb`를 전달한다.
- **고유 조건:** 길이·힘·시간 등은 입력 전체에서 일관된 단위계를 사용한다. 필요한 출력 항목은 `.feb` 안에 지정한다.

## Pulse — 생리 시나리오

- **계산 능력:** 환자 설정과 행동 시나리오에 따른 생리 반응의 시간 변화.
- **입력 → 출력:** 환자 파일·행동·시간·`DataRequest`가 있는 JSON → 요청한 생리량 시계열. 로컬 예제는 심박수 1/min, 산소 소비 mL/min, 대사율 W 등을 요청한다.
- **실행법:** 런타임 목록의 `pulse` 실행 파일에 시나리오 JSON 경로를 전달한다. [입력 형식 예제](../scripts/external_engines/pulse_exercise_smoke.json).
- **고유 조건:** 환자 등 참조 파일을 엔진이 찾을 수 있어야 한다. 반환할 변수와 단위는 `DataRequest`에서 지정한다.

## CircAdapt — 심장·순환 역학

- **계산 능력:** 심장·순환 모델의 주기적 상태 계산. 로컬 도우미는 심박수·심박출량·일회박출량·좌심실 최고 압력을 반환한다.
- **입력 → 출력:** 도우미의 `cycle_seconds`(s), `target_flow_m3_s`(m³/s) → bpm, L/min, mL, mmHg.
- **실행법:** 런타임 목록의 `circadapt` Python으로 `scripts/external_engines/circadapt_coupling.py input.json` 실행. 직접 작성할 때는 `VanOsta2023` 모델을 사용한다.
- **고유 조건:** 도우미는 안정된 심장 주기를 계산한다. 도우미의 두 입력과 네 출력이 CircAdapt 전체의 기능 범위는 아니다.

[도우미의 정확한 입출력](../scripts/external_engines/circadapt_coupling.py).

## Human-GEM — 인체 대사망

- **계산 능력:** 반응 경계와 목적함수에 따른 정상상태 대사 플럭스 최적화.
- **입력 → 출력:** `vendor/Human-GEM/model/Human-GEM.xml`, 반응 경계·목적함수 → 목적값·반응별 플럭스·해 상태.
- **실행법:** 연구 Python에서 `cobra.io.read_sbml_model(...)`로 읽고 `model.optimize()` 호출. [사용 예제](../scripts/external_engines/human_gem_smoke.py).
- **고유 조건:** 반응 ID와 플럭스 단위는 모델 파일 기준이다. 정상상태 계산에는 자체적인 시간 경과가 없다.

## MitoCore — 미토콘드리아 대사망

- **계산 능력:** 미토콘드리아 중심 대사망의 정상상태 플럭스 최적화.
- **입력 → 출력:** `vendor/MitoCore/mitocore_v1.01.xml`, 반응 경계·목적함수 → 목적값·반응별 플럭스.
- **실행법:** COBRApy의 `read_sbml_model(...)`과 `model.optimize()` 사용. [원본 워크북 변환 코드](../scripts/external_engines/mitocore_smoke.py).
- **고유 조건:** 반응 ID·구획·단위는 MitoCore 파일에서 확인한다. Human-GEM과 반응 이름이 같다고 가정하지 않는다.

## 미토콘드리아 QSP — 심근 미토콘드리아 동역학

- **계산 능력:** 초기 상태와 매개변수에 따른 심근 미토콘드리아 모델의 시간 변화.
- **입력 → 출력:** 모델 폴더, 조건별 초기 상태·매개변수·ATP 가수분해율·기간(s), 요청 상태 인덱스 → 선택한 최종 상태값과 조건별 결과.
- **실행법:** Octave에 `scripts/external_engines/mitochondria_qsp_experiment.m MODEL_DIR INPUT_JSON OUTPUT_JSON`을 전달한다. [정확한 입력 처리](../scripts/external_engines/mitochondria_qsp_experiment.m).
- **고유 조건:** 인덱스는 1부터 시작한다. 상태·매개변수의 의미와 단위는 원본 모델 정의를 따른다. 로컬 드라이버는 `ode15s`를 사용한다.

## PK-Sim — 생리학 기반 약동학

- **계산 능력:** 프로젝트에 정의된 물질·개체·투여 조건에 따른 약동학 계산.
- **입력 → 출력:** PK-Sim 프로젝트 → 설정한 농도 등 시계열을 CSV로 내보낸다. 단위는 출력 정의를 따른다.
- **실행법:** 런타임 목록의 `pk_sim` 실행 파일에 `export --project PROJECT --output OUTPUT_DIR --run --csv`를 전달한다.
- **고유 조건:** 실행 작업 디렉터리는 해당 실행 파일의 폴더로 둔다. [명령 사용 예제](../scripts/external_engines/pksim_smoke.py).

## MoBi / OSPSuite-R — 생리·물질 모델

- **계산 능력:** MoBi에서 구성한 모델을 계산하고 지정한 변수의 시간별 값을 얻는다.
- **입력 → 출력:** `.pkml`, 매개변수·초기량 → 모델 출력 경로별 값과 단위.
- **실행법:** 편집에는 MoBi GUI를 사용한다. 계산에는 R의 `ospsuite::loadSimulation()`과 `runSimulations()`를 사용할 수 있다. [R 사용 예제](../scripts/external_engines/mobi_smoke.R).
- **고유 조건:** 로컬 portable MoBi에는 CLI가 없다. 자동 계산에는 OSPSuite-R 환경을 사용한다.

## HumMod — 통합 생리 참고 모델

- **계산 능력:** 선택한 HumMod 모델의 통합 생리 상태 변화.
- **입력 → 출력:** 모델 패키지·GUI에서 지정한 조건 → 해당 모델의 생리 변수 궤적.
- **실행법:** 런타임 목록의 `hummod` 실행 파일을 사용한다.
- **고유 조건:** 이 저장소에는 HumMod용 자동 입출력 도우미가 없다. 조작과 변수 단위는 설치된 모델의 GUI·문서에서 확인한다.

## 그 밖의 모델과 자료 도구

항목의 정확한 호출 형식은 선택한 패키지의 예제·도움말에서 확인한다.
